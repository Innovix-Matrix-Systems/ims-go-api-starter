## Why this starter

<CardGrid stagger>
  <Card title="Reads like Laravel" icon="laptop">
    Thin handlers (`h.Bind`, `h.Data`), permissions on routes (`r.With(h.can("product.create"))`),
    services, repositories and one config file per section. `ims gen module` scaffolds the stack.
  </Card>
  <Card title="Multi-tenant, safe by default" icon="approve-check">
    Tenant and branch isolation in SQL that fails closed, RBAC, impersonation, per-tenant plan
    limits, and a test that fails any route without a permission.
  </Card>
  <Card title="Everything an API needs" icon="puzzle">
    Auth with OTP and recovery · billing with plan limits · settings · feature flags with rollout ·
    activity log · notifications · files on local/S3/R2/MinIO · import/export · backups · queue ·
    scheduler · RFC 9457 errors · OpenAPI.
  </Card>
  <Card title="A dashboard you'll actually use" icon="seti:html">
    Requests, logs, exceptions, queue, one-click commands, an inspector for health, routes, roles
    and config, tenants, settings, flags, files, sessions and an audit log — Ctrl+K to anything.
  </Card>
  <Card title="Fast feedback" icon="rocket">
    Type-safe SQL (sqlc), integration tests in a few lines (`testkit`), hot reload, and AI-agent
    skills that know the codebase.
  </Card>
  <Card title="One binary in production" icon="seti:go">
    No containers needed: systemd runs the API, the worker and the scheduler from the same
    binary. Prefer Docker? One image and a `compose.yaml` run the same stack.
  </Card>
</CardGrid>
